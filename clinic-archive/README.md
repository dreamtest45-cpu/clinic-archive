# أرشيف المرضى — نظام أرشفة سجلات المرضى للعيادة

تطبيق ويب مستقل بالكامل (خادم Node.js + قاعدة بيانات PostgreSQL)، لا يعتمد على أي حساب Claude — ملك للعيادة بالكامل.

## المزايا
- بيانات شخصية وتواصل لكل مريض، تاريخ مرضي وحساسية، سجل زيارات وتشخيصات، ومرفقات (صور/PDF حتى 6 ميغابايت لكل ملف)
- أرشفة بدل الحذف (يمكن حذف نهائي منفصل)
- تصدير ملف مريض كنص، ونسخة احتياطية كاملة (JSON) لكل البيانات
- تسجيل دخول بكلمة مرور واحدة مشتركة للعيادة (جلسة محفوظة 30 يوم)
- واجهة عربية بالكامل (من اليمين لليسار)، تدعم الوضع الليلي
- **قابل للتثبيت كتطبيق (PWA)**: يظهر زر "تثبيت التطبيق" تلقائياً على الحاسوب/أندرويد (كروم)، ويضيف أيقونة على الشاشة الرئيسية تفتح بملء الشاشة بدون شريط المتصفح. على آيفون/آيباد لا يوجد زر تلقائي (قيود آبل)، فتظهر رسالة صغيرة تشرح: زر المشاركة ⬆️ ثم "إضافة إلى الشاشة الرئيسية". لا حاجة لأي متجر تطبيقات أو حساب مطوّر — التثبيت يعمل مباشرة من نفس الرابط بعد نشره على Railway.

## النشر على Railway (خطوة بخطوة)

### 1. ارفع المشروع على GitHub
- أنشئ مستودع (repository) جديد وفارغ على GitHub.
- ارفع كل ملفات هذا المجلد إليه (باستثناء مجلد `node_modules` وملف `.env` إن وُجد — Railway يثبّت الحزم بنفسه، ولا حاجة لرفعها).
  - إن كان عندك Git محلياً: `git init && git add . && git commit -m "init" && git remote add origin <رابط المستودع> && git push -u origin main`
  - أو ببساطة من متصفح GitHub: افتح المستودع الفارغ ثم "Add file → Upload files" واسحب كل الملفات والمجلدات (بما فيها مجلد `public`) دفعة واحدة.

### 2. أنشئ مشروع على Railway
- سجّل دخول إلى railway.app، ثم "New Project → Deploy from GitHub repo" واختر المستودع.
- Railway سيكتشف تلقائياً أنه مشروع Node.js ويبدأ البناء (لن ينجح أول مرة لأن قاعدة البيانات غير موجودة بعد — طبيعي).

### 3. أضف قاعدة بيانات PostgreSQL
- داخل نفس المشروع: "+ New → Database → Add PostgreSQL".
- Railway ينشئ قاعدة بيانات ويعطيها متغير `DATABASE_URL` تلقائياً.

### 4. اربط المتغيرات البيئية لخدمة التطبيق
افتح خدمة التطبيق (وليس قاعدة البيانات) → تبويب Variables → أضف:

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | اضغط "Add Reference" واختر `Postgres → DATABASE_URL` (بدل كتابتها يدوياً) |
| `CLINIC_PASSWORD` | كلمة مرور قوية يختارها طاقم العيادة لتسجيل الدخول |
| `SESSION_SECRET` | نص عشوائي طويل — ولّده بالأمر `openssl rand -hex 32` أو أي مولّد كلمات مرور عشوائية |
| `CLINIC_NAME` | اسم العيادة كما تريده أن يظهر بالصفحة (اختياري) |

بعد إضافة المتغيرات، سيُعاد بناء الخدمة تلقائياً.

### 5. فعّل رابطاً عاماً للوصول
خدمة التطبيق → تبويب Settings → Networking → "Generate Domain". سيعطيك رابطاً مثل:
`clinic-archive-production.up.railway.app`

### 6. جاهز
افتح الرابط، سجّل الدخول بكلمة المرور التي وضعتها في `CLINIC_PASSWORD`، وابدأ إضافة المرضى.

## ملاحظات تشغيلية مهمة

- **تغيير كلمة المرور لاحقاً**: عدّل قيمة `CLINIC_PASSWORD` من تبويب Variables على Railway؛ ستُعاد الخدمة تلقائياً وتُطلب كلمة المرور الجديدة من الجميع.
- **النسخ الاحتياطي**: زر "نسخة احتياطية كاملة" أعلى الصفحة يُنزّل كل بيانات المرضى والزيارات كملف JSON. يُنصح بعمل هذا بشكل دوري (أسبوعياً مثلاً) وحفظ الملف في مكان آمن منفصل، بالإضافة إلى أن Railway نفسه يحتفظ بنسخ من قاعدة البيانات.
- **كلمة المرور المشتركة**: كل طاقم العيادة يستخدم نفس كلمة المرور لتسجيل الدخول (لا حسابات فردية لكل موظف حالياً). عامل هذه الكلمة مثل مفتاح العيادة الفعلي — لا تُشاركها خارج الفريق. إذا احتجتم لاحقاً حسابات منفصلة لكل موظف (بصلاحيات مختلفة مثلاً)، هذا تطوير إضافي منفصل.
- **حجم المرفقات**: حتى 6 ميغابايت للملف الواحد (صور JPG/PNG/WEBP/GIF أو PDF). الصور تُضغط تلقائياً من المتصفح قبل الرفع لتقليل المساحة.
- **الاستخدام المتزامن**: إذا فتح موظفان ملف نفس المريض في نفس اللحظة وعدّلا بيانات مختلفة، آخر من يحفظ هو من يبقى (لا يوجد دمج تلقائي للتعديلات المتزامنة). مناسب لعيادة بعدد محدود من الأجهزة، لكن يستحق الانتباه له.
- **التشغيل المحلي للتجربة**: انسخ `.env.example` باسم `.env`، عدّل القيم (تحتاج PostgreSQL محلي)، ثم `npm install && npm start`.

## الامتداد لعدة عيادات مستقبلاً
هذا الإصدار مبني لعيادة واحدة (قاعدة بيانات واحدة، كلمة مرور واحدة). لو حبيتوا تحويله لمنتج يُباع لعدة عيادات (كل عيادة بحسابها وبياناتها منفصلة تماماً)، هذا يحتاج طبقة تعدد مستأجرين (multi-tenancy) — تطوير إضافي منفصل عن هذا الإصدار.
